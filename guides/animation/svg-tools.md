# SVG animation tools — SVG.js, Anime.js, SMIL <animate>, Figma Community (read 2026-10-29)

## 1. SVG.js v3.2 — https://svgjs.dev/docs/3.2/
What it is: lightweight, dependency-free library for creating + animating SVG. MIT licence. Close to full SVG spec coverage, much shorter code than vanilla JS (their example: a pink square in 2 lines vs 10).
- Create: `const draw = SVG().addTo('#drawing'); const rect = draw.rect(100,100).fill('#f06')`
- Unified API across shapes: move(), size(), center(), groups, gradients, patterns, masks, clipping paths, text paths (even animated).
- Animation model (3 parts): element owns a Timeline (the clock); element.animate() creates a Runner on that timeline; move()/fill()/transform() calls add work to the runner.
- `animate(duration, delay, when)` — duration ms, default 400; delay default 0; when = 'after'/'last' (after previous runner ends), 'with-last' (with previous runner's start), 'now' (timeline now + delay), 'absolute'/'start' (absolute time = delay), 'relative' (shift previous start by delay).
- Chaining: `rect.animate(500).fill('#f03').animate(500).move(100,100)`; `.delay(200)` inserts a zero-duration runner between steps.
- IMPORTANT: animate() returns the RUNNER, not the element — further calls configure the animation, they do not change the element immediately. Starting values are read when the runner first executes, so a queued runner starts from the state the previous runner left.
- Runner setters (animatable): attr, css, fill, stroke, move, center, size, plot, transform, rotate, scale, translate, font, viewbox, zoom.
- Transforms: absolute (default, replaces previous transform at endpoint) vs relative (second arg true, composes with current transform). Helpers rotate/scale/translate are relative. Affine interpolation (decompose into translate/scale/shear/rotation/origin, shortest-path rotation) is the good-looking mode; matrix interpolation (6 components directly) can introduce skew/scale — pass affine=true for matrix targets. Absolute transforms replace overlapping relative ones — avoid overlapping absolute runners unless intended. Timeline seeking preserves composition both ways.
- Manual control: runner.time(), position() (0-1 within a loop), progress() (0-1 across all loops/waits), loops(), step(16) (advance ms, negative = backwards), reset(), finish(), reverse(), active(false) to skip.
- Looping: loop(times, swing, wait) — swing alternates direction, wait = ms between iterations. loop() / loop(true) = forever.
- Events/callbacks: during(position) on every step, after() on finish, on('start'/'step'/'finished'). For a side effect that must reverse correctly, derive state from position (before/active/after), not from wall-clock.
- Persistence: completed timed runners are normally removed; persist(true) or persist(ms) keeps them seekable/reversible after finishing. Set BEFORE scheduling.
- Easing: default ease-out '>'. Strings: '<>' in-out, '>' out, '<' in, '-' linear. Or a function, SVG.easing.bezier(), SVG.easing.steps(). More equations via svg.easing.js plugin.
- Controllers (not duration-based): SVG.Spring(settle time, overshoot %) and SVG.PID(p, i, d). They decide their own finish time, so they CANNOT be reliably sequenced or reversed, but they CAN be retargeted live (e.g. follow a pointer). Use for interactive previews only, never for a rendered video timeline.
- Timeline (shared clock): play/pause/stop (to 0 + pause)/finish (settle all + pause). time(ms) absolute, seek(delta) relative, speed(multiplier, negative = backwards), reverse(bool). schedule() snapshot lists start/duration/end per runner. getEndTime() = end of most recently scheduled runner (not necessarily the latest end). persist() default for runners. terminate() removes everything (vs stop, which only rewinds). Custom clock: new SVG.Timeline(() => clock) — monotonic ms source. THIS is the seek-render hook: a custom clock + timeline.time(t) gives deterministic frames, same idea as GSAP seek.
- Orchestration: assign ONE timeline to several elements (rect.timeline(tl)), then schedule with 'absolute' times or 'with-last'/'after' — pausing/seeking/speed/reversing the shared timeline affects all.
- Verdict for us: SVG.js is the best tool for BUILDING scenes (short code, unified shapes, text paths) and its timeline+custom-clock can drive frame rendering. It does NOT have SplitText-style per-character text, DrawSVG, or MorphSVG — for those, GSAP plugins win. Use SVG.js to build, GSAP to animate text/paths, or pick one per project — do not mix two timeline clocks in one scene.

## 2. Anime.js — https://animejs.com/ (homepage + docs, 2026-10-29)
What it is: JavaScript animation engine, 24.50 KB total bundle (Timer 5.60, Animation +5.20, Timeline +0.55, Draggable +6.41, Scroll +4.30, SVG 0.35 KB, Stagger +0.48, Spring 0.52, WAAPI 3.50). Small and modular.
- API: `animate('.square', {rotate: 90, loop: true, ease: 'inOutExpo'})` — per-property parameters, flexible keyframes, built-in easings.
- Transforms: individual CSS transform properties, function-based values, blend composition (e.g. x/y/rotate as separate properties that blend, not one transform string).
- Stagger: built-in stagger() — time, values, and timeline-position staggering; grid stagger with from:'center' (e.g. a 13x13 dot grid scaling from centre).
- SVG toolset (built in, only 0.35 KB): shape morphing (d: morphTo('.other')), line drawing (createDrawable(path), draw: '0 1' or keyframes ['0 0','0 1','1 1']), motion path (createMotionPath('.circuit')).
- Timeline: createTimeline().add(target, params, position) — positions like '<' (with previous) and stagger(10/200) as position. Synchronise animations, advanced time positions, playback settings.
- Playback / seek (the render hook): autoplay:false means manual play; a timeline added animation's autoplay is overridden to false. Methods: play(), pause(), restart(), seek(timeMs). HyperFrames' Anime.js adapter pattern (secondary source): create synchronously, autoplay:false, register on window.__hfAnime, finite durations/loops, then the renderer seeks each instance with instance.seek(timeMs) — exactly our Playwright seek model, in Anime.js form.
- Scroll Observer: sync/trigger on scroll with thresholds — NOT for video, only for web pages.
- Draggable + springs: drag/snap/flick/throw, createSpring({stiffness, damping}) — interactive only, not for rendered video.
- Scope: media-query-responsive animations — web only.
- Verdict for us: Anime.js is a credible lighter alternative to GSAP for a seek-rendered video (morph + draw + motion path built in, tiny bundle, seek API documented). It does NOT have SplitText or DrawSVG's dasharray control as first-class plugins, and its docs/examples are web-interaction heavy. Keep GSAP as first choice; Anime.js is the backup if GSAP's licence question ever blocks a commercial use.

## 3. SMIL <animate> — MDN, https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/animate
What it is: the native SVG animation element, Baseline "Widely available". No library needed — animation lives inside the SVG file itself.
- `<animate attributeName="rx" values="0;5;0" dur="10s" repeatCount="indefinite" />` inside a <rect> animates that attribute over time.
- Related elements (same module): <animateTransform> (transform), <animateMotion> (along a path, with <mpath>), <set> (instant change at a time).
- Why we do NOT use it as the main engine: it runs on wall-clock in a browser, it cannot be paused + seeked frame-by-frame as reliably as a JS timeline, and Chrome has deprecated SMIL in the past (it was kept, but the direction of the web is CSS/WAAPI/JS). It IS useful for: a self-contained SVG file that must animate without any JS (e.g. an animated icon/logo delivered as a single .svg), and for simple loops.
- Accessibility note from MDN: blinking/flashing can harm users with ADHD, vestibular disorders, epilepsy, migraine, Scotopic sensitivity. Provide pause/disable, respect prefers-reduced-motion. (Matches IBM + U-M rules.)
- Verdict: keep SMIL in the toolbox for standalone animated SVGs only. Our video pipeline stays JS-timeline + seek + screenshots.
