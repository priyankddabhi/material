# PROCESS / QC — mind topic

## GIT-006 — 2026-10-29 — GitHub design scoring rubric (pre-show self-score)
SOURCE: https://github.com/saimuthiki/startup_agency/blob/HEAD/.claude/skills/top-design/SKILL.md
RULE: Score every demo BEFORE showing the user: typography scale
contrast, composition tension (not centred-everything), colour ownership,
craft details. Template-like / generic feel = fail, redo before presenting.
APPLY: quick gut-score 0-10. Below 7 = do not show; fix the weakest axis
first (usually scale contrast or negative space).
CHECK: if the demo could belong to any brand, it belongs to no brand —
add one owned detail (accent, texture, prop) and re-score.

## REEL-005 — 2026-10-29 — reel DdUOsyaS-Zz (diagnose, then fix boldly)
RULE: Before fixing a flat demo, NAME the exact weakness first — then
fix that one thing boldly, not with a small general tweak.
DIAGNOSIS TABLE (from the reel):
- Looks boring → adjust the LAYOUT.
- Doesn't stand out → EXAGGERATE the scale (oversized hero).
- Looks plain → add more DETAILS (a few, not clutter).
- No focus point → use CONTRAST.
APPLY: on every flat demo, say the diagnosis in one word (layout /
scale / detail / contrast) BEFORE changing anything. Then apply only
that fix, boldly: hero oversized + off-centre against a strongly
contrasting background, one short large headline, few supporting props.
NEVER: small centred product + several equal-sized text lines on a
similar-coloured background.
CHECK: after the fix, the weakness word must be gone. If you cannot name
the weakness, you are guessing — stop and look again.
EXAMPLE FROM THE REEL: "BAG CULTURE" poster — very large title + large
dark oval bag image (scale exaggerated, not nudged).
